# v0.1 architecture: policy evaluation and audit

Date: 2026-10-14
Status: Planned baseline; implementation contracts are tracked in [requirements](../requirements.md)

## Service boundary

AgentWall is a modular Go monolith with a native Go policy evaluator, a Git policy synchronizer, persistent local bundles, and PostgreSQL audit storage. Deploy one service instance for one organization using Docker Compose.

The hot path is authentication → trusted assertion validation → evaluation against one immutable snapshot → audit queue admission → response. Git access, policy preparation, and audit database writes occur outside the normal evaluation path. In-flight requests may finish on an earlier snapshot; each response and event must identify that snapshot's revision.

Applications enforce decisions. A decision does not establish that an action executed or that an external caller truthfully represented its users. API keys establish service identity and constrain assertions, not verified end-user delegation.

## Policies and lifecycle

Policies use `agentwall.dev/v1alpha1`, `kind: AgentPolicy`, metadata, effect, subjects, actions, resources, and typed conditions. YAML is validated into typed policy structures and compiled into an immutable condition tree evaluated directly in Go. The evaluator implements a bounded set of matching and comparison operators; policies cannot execute arbitrary code, scripts, or template expressions. No OPA or Rego dependency is required.

Allow requires a matching allow and no matching deny. Directories organize domains but do not confer precedence. Unknown fields, invalid types, unsupported versions, and failed policy tests reject the candidate.

Fetch configured Git ref → validate → test → prepare evaluator → persist and verify immutable bundle → atomically activate. Poll every 60 seconds by default. Persist revision, digest, schema/evaluator compatibility information, and recovery metadata. Digests alone do not authenticate a bundle against malicious local replacement.

Rollback selects a previously validated bundle and persists a pinned state. Polling cannot undo it. Explicit resume reconciles with Git. Startup restores validated last-known-good state, including the pin; without a usable bundle, authorization remains unavailable.

## API and identity

Planned endpoints:

| Endpoint | Purpose |
| --- | --- |
| `POST /v1/authorize` | Evaluate an action |
| `GET /v1/audit/events` | Scoped, filtered, paginated decision queries |
| `GET /v1/audit/events/{id}` | Scoped event lookup |
| `GET /health/live` | Process liveness |
| `GET /health/ready` | Operational readiness |
| `GET /metrics` | Restricted Prometheus metrics |

Requests describe principal, agent/session, action, resource, and context. The service caller is derived from the API key. Unauthorized identity assertions are rejected. Responses contain `decision_id`, `allow`, `reason_code`, and `policy_revision`; reason codes include `POLICY_ALLOW`, `EXPLICIT_DENY`, and `DEFAULT_DENY`.

Keys have operation scopes and assertion constraints, secure generated secrets, non-secret lookup IDs, and hashed secret storage. CLI management covers create/list/rotate/revoke, audit queries, rollback, and explicit synchronization resume. Administrative access is separate from application keys. Exact syntax and authentication are contract work.

## Audit and operations

Use a bounded in-memory queue with batched PostgreSQL writes, bounded retries/backoff, and unique decision IDs. Default strict mode rejects requests if events cannot enter the queue. Best effort may continue with explicit loss counters. Accepted events can still be lost on crash; no durable-before-response, tamper-evidence, or execution-outcome guarantee is made.

Retention defaults to 90 days, is configurable including indefinite retention, and uses bounded cleanup batches. Audit access is scoped. Sensitive request data must be minimized and credentials excluded from records and telemetry.

Expose request counts/latency, evaluator errors, active revision, last successful synchronization, queue depth, dropped events, and audit write latency/failures. High-cardinality identifiers belong in restricted logs/traces/events, not metric labels. Graceful shutdown has a bounded drain deadline.

Readiness must account for usable policy state and the chosen audit admission contract; database outage does not automatically imply immediate queue exhaustion. Resolve exact readiness and retry behavior before implementation.

## Internal organization

Introduce packages as needed for authentication, authorization, policy schema/compiler/evaluator/loader/repository, audit, credentials, storage, telemetry, and HTTP transport. Keep interfaces at real boundaries; avoid speculative gateway/runtime frameworks. Retain the existing entry point until moving it serves implementation needs.
