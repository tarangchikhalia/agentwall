# v0.1.0 — Test environment design brief

This document states the agreed scope and design work; it does not select tools or claim acceptance.

## Goal and scope

Create reproducible agents, protected resources, scenarios and measurements. Use two or three agents and controlled resources. Define permitted, denied and invalid-authority cases with explicit expected outcomes. Use repeatable request fixtures so model variability does not obscure correctness or latency.

Measure direct-path latency, throughput and errors as the baseline for later AgentWall comparisons. This milestone creates the harness; it does not claim AgentWall already enforces the expected decisions.

## Design work before implementation

1. Select agents, controlled resources and the bounded action/resource case that can support the first enforced slice.
2. Specify scenario inputs and expected outcomes, including permitted, denied and invalid-authority cases. Distinguish future authorization expectations from observed direct-path behavior.
3. Define fixture repeatability and a reproducible execution procedure.
4. Define baseline metric collection, workload conditions, result recording and reproducibility criteria.
5. Turn the design into bounded implementation tasks and explicit acceptance checks.

## Completion evidence

- Scenarios run reproducibly against the documented environment.
- Expected outcomes are explicit and documented.
- Direct-path latency, throughput and error measurements are recorded with reproduction conditions.

Concrete agents, resources, protocols, metric thresholds and implementation tasks remain open until design. No inherited policy/audit M0–M5 gate applies to this milestone. The next milestone, v0.2.0, verifies real enforcement and correlated evidence end to end.
